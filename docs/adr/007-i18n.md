# 007. Multilingual Interface, Input Language & RTL Architecture

Date: 2026-11-21
Status: Accepted (Expanded roster, dual Output/Input model & Profile quick-switch pinning approved)

## Context

ExoNovel serves global writers and readers across Europe, the Middle East, East Asia, South Asia, Africa, Latin America, and North America on **Web, Linux, macOS, Windows, Android, and iOS**. A user may read ExoNovel's menus in one language while drafting a novel or chatting with collaborators in another—and multi-script, bidirectional (**RTL + LTR**) content must work seamlessly without bloating WebAssembly downloads or cluttering language dropdowns.

## Decision

### 1. Two Distinct Language Dimensions: Output (UI) vs. Input (Authoring & Chat)
1. **Output / App UI Language (`ui_locale`)**:
   - Controls all navigation, menus, buttons, Preferences, Profile labels, notifications, and system messages globally across the signed-in account.
   - Stored in **`user_profiles.ui_locale`** (Neon PostgreSQL + `willow25` profile path) and injected into server-rendered `<html lang="..." dir="...">`.
2. **Input / Content Language (`default_input_locale` + Per-Composer Override)**:
   - Controls the language of creative writing, chapters, story-architecture notes, comments, and live chat messages.
   - Users set a default in Profile/Preferences and can switch **input language on the fly** directly inside any composer or chat box without changing the global app UI language.
   - Drives element-level HTML `lang` and `dir` (`ltr` / `rtl` / `auto`), browser/OS spellcheck & IME keyboard hints, hyphenation, and searchable language metadata on created works and messages.

### 2. Web On-Demand Loading, Decentralized Device Packs & Profile Quick-Switch Pinning
- **Web Performance & Loading Strategy**:
  - `leptos-fluent` (`0.3.1`) paired with Mozilla Fluent (`.ftl`) uses compile-time static embedding (`static_loader!`) by default, which bakes every locale into the WASM binary (~20–30 KB uncompressed per language, shrinking ~50% under Brotli compression).
  - On the web, ExoNovel uses **on-demand `.ftl` loading** (`ArcLoader` on the Rust/Axum SSR server + cached `/api/i18n/{locale}.ftl` hydration in WASM, preloading only the active UI language) so 29+ languages add zero unused-locale WASM bloat.
- **Decentralized Desktop & Mobile Offline Language Packs**:
  - Native builds (**Linux, macOS, Windows, Android, iOS**) bundle the user's base/OS language(s) at install time so zero-server/local-only devices boot offline cleanly.
  - Inside **Preferences → Languages**, decentralized users subscribe to and cache any additional `.ftl` language packs directly from ExoNovel's **public read-only `willow25` / `iroh-blobs` namespace** (with HTTPS fallback), keeping full offline autonomy afterward without relying on a central database.
- **Personal Quick-Switch Pinning & Flag-First Switcher**:
  - All supported languages remain accessible to every user via **Preferences → Appearance & Languages**—no user is ever locked out of a language.
  - The top-bar GitHub-styled language switcher (`exo-lang-trigger` / `exo-lang-menu`) displays each language's crisp inline SVG flag **preceding** its native name (`[Flag] Polski`, `[Flag] Deutsch`, `[Flag] English`) for consistent cross-browser rendering across Linux, Windows, macOS, and mobile browsers.
  - Inside their **Profile**, users select which languages to **pin** into their **Output (UI) Quick-Switch** (`preferred_ui_locales[]`) and **Input Quick-Switch** (`preferred_input_locales[]`) so frequent switchers only flip through their 2–4 chosen languages with one click.

### 4. Bidirectional Layout, Typography & Zero-`localStorage`
- Logical CSS properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end`) mirror navbars, sidebars, drawers, and reading controls cleanly whenever `ui_locale` is `ar` or `he` (`dir="rtl"`), while individual RTL/LTR manuscripts inside an opposite-direction UI stay properly aligned via per-editor `dir`.
- Typography stacks cover Latin, Extended Latin (for Yoruba/Hausa/Igbo/Polish/Hungarian/Romanian), Cyrillic (`uk`, `ru`, `sr`), Greek (`el`), Arabic (`ar`), Hebrew (`he`), CJK (`zh-Hans`/`zh-Hant`), Ethiopic (`am`), and Indic (`hi`, `bn`, `mr`, `te`, `ta`).
- Navigation/cards enforce 25–30% horizontal/wrapping headroom for longer European & Indic phrases, with all user preferences persisted in Neon PostgreSQL + `willow25` (zero `localStorage`, see [002-004](002-data/004-db-prefs.md)).

### 5. Synchronized Multilingual Documentation Editions (`adr_translations` — Proposed Schema)
- Under `AGENTS.md` Rule 18, all ADR updates apply across every active documentation language edition (`en` canonical, plus active translated editions such as `de` and `pl`).
- Rather than cloning empty placeholder rows into Neon automatically whenever a UI locale is toggled, the proposed data-driven design pairs canonical `adr_records` with a child `adr_translations` table (`adr_id`, `locale`, `title`, `raw_markdown`, `rendered_html`, `source_updated_at`, `translated_at`, `PRIMARY KEY (adr_id, locale)`), falling back cleanly to English whenever an edition is missing or marked `stale` (`source_updated_at < adr_records.updated_at`).
