# 005-003. Oparty o dane CMS Dokumentacji ADR i Dojrzałości Narzędzi

Data: 2026-11-21
Status: Zaproponowano (realizacja w trakcie odbioru)
Nadrzędny: [005-docs-ui](../005-docs-ui.md)

## Kontekst

ExoNovel rozwija się równolegle z dojrzewaniem kluczowych technologii (`willow25`, `iroh`, silniki CRDT w Rust, `leptos`, globalni dostawcy płatności). Funkcje oczekujące na wydania zależności otrzymują status **`on-hold`**. Dlatego czytnik działa jako **oparty o dane CMS MADR 4.0.0 i Dojrzałości Narzędzi** w **Neon PostgreSQL**.

## Decyzja

### 1. Baza danych jako główne źródło prawdy
- Tabele **Neon PostgreSQL** przejmują zarządzanie treścią po starcie serwera (z automatycznym importem brakujących plików `.md` z `docs/`).

### 2. Relacyjny model danych MADR 4.0.0 i Dojrzałości
- **`adr_records`**: `id`, `adr_number`, `parent_adr_id`, `doc_kind`, `title`, `slug`, `status` (`proposed`, `accepted`, `on-hold`, `ready-to-build`, `rejected`, `deprecated`, `superseded`), sekcje MADR, pola RACI i współrzędne `willow_*`.
- **`tooling_catalog` i `tooling_versions`**: Katalog obserwowanych bibliotek, SDK i protokołów wraz z historią wydań semver.
- **`adr_tooling_dependencies`**: Łączy zablokowane dokumenty ADR z docelowymi wersjami, umożliwiając automatyczne odblokowanie do **`ready-to-build`**.
- **`adr_translations`** (Zsynchronizowane wydania wielojęzyczne wg `AGENTS.md` Reguła 18):
  - `id`, `adr_id` (FK -> `adr_records`), `locale` (`de`, `pl`, ...), `UNIQUE(adr_id, locale)`
  - Przechowuje przetłumaczone tytuły, pola MADR i `raw_markdown`, dzięki czemu edycje w języku polskim lub niemieckim nie nadpisują kanonu angielskiego, a brakujące wpisy płynnie wracają do wersji angielskiej.
- **`maturity_proposal_notes`** (Propozycje rozwojowe z nowych wydań):
  - `note_id`, `tool_id`, `version_id`, `adr_id`, `proposed_by`, `proposal_title`, `new_capability_summary`, `how_exonovel_benefits`, `review_status` (`open`, `accepted`, `dismissed`), `created_at`
  - Zawiera przycisk **Utwórz szkic ADR z propozycji** (**Draft ADR from Proposal**), który jednym kliknięciem wypełnia edytor MADR danymi propozycji.

### 3. Rozdzielony interfejs CMS
- **Boczny eksplorator drzewa i filtrów**: Nawigacja hierarchiczna i filtrowanie po statusie/typie; automatyczne zwijanie po wybraniu dokumentu na urządzeniach mobilnych.
- **Strukturalny edytor MADR**: Edycja i tworzenie w aktywnym języku interfejsu (`en`, `de`, `pl`).
- **Widok „Narzędzia i Propozycje“** (rozdzielony od konfiguracji modeli AI): Katalog zależności, deterministyczne skany `crates.io` / GitHub oraz generowanie i promowanie **Propozycji dojrzałości** (`Utwórz szkic ADR z propozycji`).
- **Widok „Inferencja AI“**: Oddzielny panel administratora wyłącznie dla skonfigurowanych środowisk uruchomieniowych (`OpenCode` CLI + aktywne klucze takie jak `NVIDIA NIM`), aktualnych darmowych modeli i odświeżania katalogu.

### 4. Automatyczny skaner dojrzałości a Dependabot
- **GitHub Dependabot (`.github/dependabot.yml`)**: Cotygodniowe, grupowane aktualizacje `lockfile-only` wyłącznie dla już zainstalowanych zależności (`Cargo.lock` i `.github/workflows/*.yml`).
- **Deterministyczny skaner Rust + opcjonalna synteza `OpenCode`**: Przetwarza `crates.io` i wydania GitHub deterministycznie, a dla propozycji wywołuje **`opencode run --standalone --auto --format json`** z rezerwowym wywołaniem aktywnych darmowych modeli (`NVIDIA NIM`; zobacz [004-inference](004-inference.md)).
